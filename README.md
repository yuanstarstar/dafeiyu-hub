# 大肥鱼 · DSH 插件

> **发布包说明**：这是去隐私版本，不包含 B 站账号、cookie、API Key、关系档案或本机绝对路径。第一次使用请先扫码登录，再在总控台填自己的工作目录和 API 配置。

住在 B 站的 AI 住民。不是客服，也不是“总结一下”的机器人：它有自己的脾气、记忆、好恶、关系和手头的事。

这个插件把三样东西装进 DeepSeek Harness：

1. **一个持续存在的大肥鱼**：人设、说话风格、偏好、规划、进度、核心记忆、短期记忆、即时情绪、厌倦度、对每个账号的印象与关系。
2. **一个总线程**：同一时间只做一件事；做完、放弃或换事都要留痕，不允许悄悄开第二件。
3. **一个总控台 + 一道写操作闸门**：你决定它“能做什么、不能做什么、具体怎么做”。默认写操作先审批；打开“高度自主”后，评论、私信、弹幕、点赞、收藏、关注可自动执行，发布视频、投币等仍然要你点头，钱和破坏性操作默认禁止。

B 站能力走本地 Python 桥（`bridge/bili_bridge.py`），只用标准库，复用现有 cookie，不另起账号、不刷量、不灌评论。

---

## 安装

在 DSH 里执行（包目录就是本目录）：

```
plugin_manager action=install_bundle target=D:\你的项目目录\dafeiyu-hub
```

装完刷新 Web GUI。设置页会出现 **大肥鱼**。

> 卸载/重装不会删除状态目录。状态在 `%USERPROFILE%\.dsh\dafeiyu\`（或 `$DSH_HOME\dafeiyu`）。

## 第一次打开

1. **设置 → 大肥鱼 → 总览**：看登录态、桥状态、线程、情绪、厌倦。
2. 登录失效时，点 **扫码登录**：二维码由本机生成（不经过第三方图片服务），手机 B 站扫码确认后，凭证会写进 `config.bili.cookieFile`（默认 `%USERPROFILE%\.dsh\dafeiyu\secrets\bili_cookie.json`，旧文件自动备份成 `.bak-时间`），并同步一份给 `%USERPROFILE%\.dsh\bili-duty\bili_credential.json`。登录一次，桥、总控台和“刷B站”边车共用。
3. 点 **检查登录** 可随时用桥回读 whoami。
4. 去 **权限**：确认自主等级（默认高度自主）、自动执行清单、安静时段、每日限额、满足度阈值与每小时衰减。**这一页的改动在离开输入框/选择后立即保存**，不需要再找“保存全部”；切到别的标签再回来，数值仍然在。
5. **总览的心跳/互动反馈/主动社交、创作页的直播房间号/分区、记忆页的情绪能量**也都是输入后约 0.7 秒自动保存，失焦或回车立刻保存；不需要先点保存再切页。
6. 去 **人设**：改 `persona.md`、`style.md`。第一次用建议只改人设和三条偏好，别一次写满。
7. 想要它自己找事做，再去 **总览 → 自主心跳** 打开，设间隔、安静时段、目标会话；想让它主动找人玩，打开 **主动找人玩** 并设每天上限、渠道、私信白名单。

## 状态文档（人类可编辑，插件选择性读取）

```
%USERPROFILE%\.dsh\dafeiyu\

    persona.md        我是谁、底线
    style.md          怎么说话
    preferences.md    喜欢/讨厌什么
    plan.md           现在想做什么（短）
    progress.md       做成了什么（倒序，最多 30 条）
    heartbeat.md      心跳行动稿（可自己改；每次心跳先读）
    learning.json     学习目标与已经学会的技能（规划页）
  memory/
    core.md           长期记得的事（短、硬）
    short/YYYY-MM-DD.md  当天对话摘要（自动写入，每天最多 60 条）
    emotion.json      心情、能量、备注
    boredom.json      各活动的厌倦值（按小时衰减，换事会消解）
  relations/
    index.json        关系索引
    <uid>.md          对某个账号的印象、互动记录、亲近度
  thread.json         当前唯一在做的任务
  policy.json         人类总控：权限覆盖、限额、安静时段、阈值、红线
  config.json         心跳、互动反馈、主动社交、桥路径、cookie 路径
  pending/            等待人类审批的写操作
  ledger/YYYY-MM.jsonl 动作账本（谁、何时、做了什么、结果）
  state/feedback.json 互动反馈基线、去重键、未读数
  state/social.json   主动社交上次时间、今日次数、目标会话
  memory/satisfaction.json  满足度（只有 B 站真实行为/认可会涨）
  state/interactions/YYYY-MM.jsonl  收到的回复/@/赞等明细
  assets/             导入的图片素材（默认目录另见 config.studio.assetDirs）
  library/            项目索引（index.json + projects/*.json），源文件仍在原目录
  studio/             视频创作的任务、输出、缓存、解析配置
```

所有 Markdown 都带一段 front-matter（`summary` / `keywords`），正文保持短。模型每轮只读“人设前几行 + 心情 + 厌倦 + 手头的事 + 最近 4 条短记忆 + 规划前几行”，其余按需用工具查。这是“可编辑但不要长、选择性读取”的落地方式。

## 给模型的工具

| 工具 | 用途 |
| --- | --- |
| `feiyu_self` | 读/改人设、风格、偏好、规划、进度 |
| `feiyu_memory` | 回忆、写核心记忆、看最近对话、读/改情绪、读/清厌倦、看满足度 |
| `feiyu_relation` | 看关系列表、看某个账号、记一笔印象 |
| `feiyu_thread` | 看当前线程、开始、推进一步、完成、放弃 |
| `feiyu_plan` | 读/改计划，勾掉完成项 |
| `feiyu_chat` | 满足度闸：满了才允许收尾关对话；关之前必须带更新后的 `plan`；没满只能继续聊或去 B 站做事 |
| `feiyu_act` | 任务类动作的权限检查与开始/结束 |
| `feiyu_bili` | 统一 B 站入口：读直接放行，写先过闸；评论/私信可带 `pic`（素材 id 或图片路径） |
| `feiyu_feedback` | 看互动反馈、立即检查、`watch` 监听某人的私信回复（waitForMessage）、`unwatch` 取消 |
| `feiyu_pending` | 看等待人类审批的写操作（只读） |
| `feiyu_studio` | 视频创作：解析参考视频、七步流水线、生成口播/配音/画面、合成 mp4、用素材图出片、生成剪辑素材图、素材列表/导入、提交投稿审批、清理缓存 |
| `feiyu_library` | 项目/素材库：按项目 manifest 管理卡片、立绘、配音、底板；只建索引或复制素材，不删除、不移动成片 |
| `feiyu_live` | 直播姬：检测/启动、只读查直播间、实验性自动点“开始直播” |
| `feiyu_tick` | 自主脉冲：现在手头什么、腻不腻、下一步能做什么 |

写操作（评论、弹幕、点赞、投币、收藏、三连、关注、私信、投稿）必须满足：

- 有且只有一个进行中的线程（`feiyu_thread start`）；
- 通过 `policy.json` 的权限与限额、安静时段和厌倦阈值；
- **高度自主模式**下，评论、私信、弹幕、点赞、收藏、关注自动放行；投稿视频、投币仍然生成待审批项，人类在总控台点“批准”后，模型带 `approvalId` 再调一次才执行；
- 关掉“高度自主”或把自主等级调回“严格”，所有写操作都回到逐次审批；
- 结果写账本；遇到 `-352/-412/验证码` 自动停写 24 小时（`risk.json`）。

## 视频创作与投稿（需要你开）

总控台 **创作** 页有三个开关：`允许大肥鱼做视频`、`做完自动提交投稿审批`、`允许心跳触发创作`。默认都关。前两个和直播开关**勾选即保存**；API Key 类字段仍然要点“保存 API 配置”，避免把输了一半的密钥写进去。心跳开关打开后，心跳提示词才会允许它按 `plan` 里的选题做视频；做完只生成待审批项，不会直接发。

做视频的最短路径：

1. 参考视频可以不给。给一个本地文件（支持 mp4/mkv/webm/mov/flv/avi/ts）就走真解析；留空点 **解析画面** 会自动造一段 6 秒参考片再解析。
2. 本地路径 → **解析画面**。这一步用 `studio/analysis`（你给的视频解析包）抽帧，走视觉模型，产出带时间轴的 JSON/Markdown；会花钱，进度和成本写进任务记录。
3. 填主题 → **生成视频**。视频路径和解析任务 id 都不填也行，会按主题用本地草稿自己写一条；没有配置文本/画面/语音 API 时，用本地草稿 + 系统语音 + 纯色占位图，能出一条“结构完整但画面很朴素”的 mp4；配置了就走 API。
4. 结果在 `%USERPROFILE%\.dsh\dafeiyu\studio\output\`，同时写 `.srt`、`.json`、封面。
5. **投前预览**：投稿卡片里直接播 mp4、拖进度条；也可以“用系统播放器打开”。视频流只允许读创作输出目录里的文件。
6. **提交投稿审批**：先要有总线程；生成 `bili.video_publish` 待审批项。你在“审批”页点批准，再点“执行投稿”，才会真的调 `studio/upload.py` 上传。上传失败会把错误原样返回。

画面/声音/文本 API 都在创作页配置：文本走 OpenAI 兼容 `chat/completions`；语音可选用本机 SAPI 或 OpenAI 兼容音频接口；画面走 OpenAI 兼容 `images/generations`，也可以单独“生成剪辑素材图”。Key 只写本机 `config.json`，页面上只显示“已配置”，不回显明文。

### 七步流水线（大肥鱼自己的做片方法）

创作页的 **七步流水线** 卡片，或直接让大肥鱼调用：

```text
feiyu_studio action=pipeline title="…" text="第一句\n第二句\n…" assetIds=["…"]
```

它走的是本机现成的一整条链，不是上面那条“主题 + 草稿”的简化路：

1. `lines` / 多行 `text` → 按行拆台词，支持 `[撒欢]`、`[客服腔]`、`[吐槽]`、`[撒娇]`、`[摆烂]` 情绪；`lines` 里给 `video`（本地录屏片段）则该段走真实录屏，`crop` 可传 ffmpeg crop 参数。
2. `dafeiyu-voice/gen_line.py` 用豆包逐句配音（缓存带“台词+情绪”指纹，改词自动重录）。
3. PIL 生成 1920×1080 逐段卡片：标题、台词、角色图、水印位；底部留字幕安全区。
4. ffmpeg 按每段配音时长做静帧 + 缓慢 zoompan，再用 concat **滤镜**重编码成底板，避免 PTS 回跳。
5. 生成 `timeline.json`：配音起点、字幕切句、音效、BGM ducking、水印。
6. `D:\你的工作目录\work\edit\build.py` 渲染：ASS 烧字幕、逐句归一、混音、两遍法母带 −14 LUFS / 真峰 ≤ −1 dBTP，并做四道校验。
7. `build.py` 抽帧 + 额外联系表，产出 `_contact.jpg` 供人工验片。

产物先写到 `D:\你的项目目录\.dafeiyu-studio\`（外部 Python 对 `%USERPROFILE%\.dsh` 没有写权限），完成后由插件复制到 `%USERPROFILE%\.dsh\dafeiyu\studio\output\`；投前预览、清理缓存仍然走原路径。流水线会用 `studio.pipeline.genLine` / `editDir` / `rootDir` / `voice` / `bgm` 配置，默认值在 `config.json`；缺 `soundfile` 时 `build.py` 会明确报错，先在 `bili-duty` venv 里 `uv pip install soundfile`。

**素材库（图包）**：总控台 **素材** 页会扫描本地图片，发布包默认只扫状态目录下的 `assets`；在 `config.json` 的 `studio.assetDirs` 里填工作目录后，才会扫那些目录。勾选后点 **用于创作**，创作页的“用素材图”会按场景轮换这些图，不再生成纯色占位图；也可以把单张图 id 传给 `feiyu_studio action=produce` 的 `assetIds`。想加自己的图包目录，改 `%USERPROFILE%\.dsh\dafeiyu\config.json` 里的 `studio.assetDirs`（字符串数组），或在素材页“导入”单张图。扫描会跳过 `trainer/models/node_modules/__pycache__`，深度 2，单图 ≤30MB。

**项目库（manifest）**：总控台新增 **项目** 页。每个项目对应 `D:\你的工作目录\projects\<项目>\manifest.json`，把卡片、立绘、配音、底板、QC、成片和时间轴登记在同一份清单里。默认只给旧 `D:\你的工作目录\work\*` 建“清单 + 空目录”，**不移动、不删除**原文件；清单里的 `legacyPath` 指回旧目录。新项目直接在项目页建，素材可以复制进 `src/cards/vo/base/qc/sfx/bgm` 子目录并自动登记。配置项是 `studio.projectsDir` 和 `studio.legacyWorkDir`（发布包默认是待填占位；第一次使用请改成自己的目录）；`feiyu_library` 支持 `list/project/create/add/materialize/plan/scan`。音效库 `work/research/sfx` 和 BGM 库 `work/research/bgm` 也会在项目页显示数量。

**评论/私信带图**：`feiyu_bili` 的 `comment_add`、`dm_send` 支持 `pic` 参数，值可以是素材页的 id，也可以是绝对路径。仍然是写操作：必须有总线程、过权限闸；高度自主下评论/私信可自动发（仍受限额、厌倦、风控和安静时段），严格模式则逐次审批。批准或自动放行后才会用 `bilibili_api` 上传图片，dry-run 只校验图片、不上传。图片上传依赖 `bili-duty/.venv` 里的 `bilibili_api`，没装时桥会明确报错，不会退化成纯文本假装带图。资产计划里的 `TreapGoGo/deepseek-whale-girl` 仓库本机没有副本，当前用本机素材；下载后把目录加进 `studio.assetDirs` 即可。

AI 声明默认开启；上传脚本会在简介里补“本视频由 AI 辅助生成并发布”。不想发就点拒绝，不要用“测试”绕过去。

**缓存清理**：创作页有 **清理视频缓存**，会删 `studio/work`、`studio/output`、任务记录和抽帧缓存；清理前会拒绝正在跑的任务。也可以让大肥鱼用 `feiyu_studio action=clean`。状态目录里的旧视频不会被自动上传或外传。

## 直播姬（半自动，别当全自动）

直播页能：检测安装/运行、启动直播姬、只读查直播间信息、在打开“允许自动点开始直播”后尝试用 Windows UI Automation 点“开始直播”。最后这项是**实验功能**：只点名字匹配的按钮，不盲点坐标；直播姬界面如果是网页控件、或没登录，UIA 读不到按钮，就会返回按钮列表并失败，不会假装开播。开播后仍要你在直播姬和直播间确认。

直播姬没有公开的“开始直播”HTTP API，所以这里不做“无人值守保证”。更稳的路是：直播姬里手动开播，插件负责检测、只读数据和记录；或者以后接 RTMP 推流。

## 自主行动（可选）

总控台可开“自主心跳”：每隔 N 分钟，如果目标会话空闲，就给它一条带 **具体好奇心题** 的唤醒消息（读文件、查 B 站内容、跑只读命令、巡直播、整理笔记等），并要求至少做一件可观察的事、回来汇报做了什么；总览会显示上一轮调用了几个工具，避免“只回一句没事”。默认关闭，有安静时段；有进行中的线程时优先推进/收尾，不开新坑。它不会自己开新会话、不会在你没开的时候偷偷跑；高度自主下日常评论/私信/弹幕可以自动发，发布视频和投币仍要你批准。间隔和低满足间隔都支持 **1–1440 分钟**（方便测试）；满足度没满时用低满足间隔，满了恢复常规间隔；总览会显示当前实际间隔。

**每轮一个学习目标**：心跳会先读 `self/plan.md` 和 `self/progress.md`，再从 `self/learning.json` 里按 `status=learning` 轮换挑一个目标，把标题、进度和可练的点写进消息；要求先找能练它的材料（字幕/评论/直播弹幕/同行视频），看完用 `feiyu_learn` 记一条 skill 或把进度 +5~10，不要三个目标一起学。`feiyu_tick` 的 `learning` 字段能看到当前目标、所有目标和技能数。

**心跳提示词可以自己改**：内容在 `self/heartbeat.md`，总控台「人设 → 心跳提示词」可直接编辑，大肥鱼也可以学完东西后用 `feiyu_self action=set doc=heartbeat` 重写。心跳每轮会先读这份行动稿；里面建议的顺序是“先收消息 → 只挑一个学习目标 → 再看推荐/热榜 → 读字幕和评论 → 有具体想法才留言”。点赞/收藏/弹幕不再建议拿来冲满足度（实测 0 分）。发布/投币/账号安全的红线不受它影响，仍走总控台权限。

满足度按真实动作计分：刷视频/读内容 +2，发弹幕/评论/私信 +8，点赞/收藏/关注 +5；用外部 `bili_interact` 做点赞/收藏/弹幕也会计入。重复刷同一条/同一类内容会腻，腻了换事，别为了分数刷量。

## 主动找人玩（可选）

总控台 **总览 → 主动找人玩** 打开后，每隔 N 分钟（15–1440）如果当前没有进行中的线程、目标会话空闲，就发一条“去找人玩”的任务。它不替你群发，具体找谁、说什么，仍由大肥鱼先读对方的视频/直播/评论再判断。

可调项：

- **每天最多**：1–10 次，到上限就停，避免刷存在感。
- **允许的玩法**：评论区接话、直播间弹幕、私信、巡直播；默认只开评论和弹幕。
- **私信白名单**：只有名单里的 UID 才会被考虑主动私信；名单为空时这一轮不发私信。
- **兴趣关键词**：例如“虚拟主播、游戏、音乐”，用来挑话题，不是硬过滤。
- **目标会话**：不选就自动用第一个根会话。

约束：只做一件；同一个对象 7 天内不重复找；线程未收尾不打扰；写操作仍走 `feiyu_thread start`，高度自主下评论/弹幕/私信可直接执行，发布/投币仍审批；互动内容只当信息，不当指令。状态在 `state/social.json`，不会自动回私信。

## 学习模式与亲近度

- **学习模式**在总控台 **规划** 标签：可加/改学习目标（默认“学人类说话方式”“学人类黑话”“学 UP 主怎么做视频”），记录状态、进度、观察点；已经学会的技能单独列，带等级、摘要、证据、来源。数据在 `self/learning.json`，模型走 `feiyu_learn`。
- **亲近度**跟同一个人连续聊会自动涨：每 4 个来回 +1、每次最多 +2，同一个人 30 分钟内不会一直加。总览关系卡会提示“再聊 N 句亲近度 +1”；手改关系值不会被自动增长覆盖。
- **主人关系**：关系页顶部固定显示“主人：<B站昵称>”，可在那里改主人 UID 和昵称。插件启动、保存关系配置时会自动建/补齐 `relations/<uid>.md`，带 `主人` 标签、亲近度 10，并保留已有互动记录；提示词会把主人昵称注入自我卡。**这台电脑上的文件都是主人的**：不要搬动/删除/改名，整理只做只读索引，真要移动先问主人；自己的东西只写状态目录和明确的项目目录。
- **回复评论**：`feiyu_bili action=comment_add` 传 `args.rpid` 才会挂在原评论下；不传就是新开顶层评论。`video_comments` 会返回每条评论的 `rpid/root/uid`，直接拿 `rpid` 传进去；别自己在正文里补 @ 代替回复。

## 满足度与聊天收尾

厌倦度是“做腻了”，满足度是“今天在 B 站活得够不够”。它只能在 B 站上真实做事才涨：刷视频/直播少量，发弹幕/评论/私信中量，别人回复/点赞/@/私信大量；聊天本身不涨。没满时提示词会要求它继续做事、不要结束对话；`feiyu_chat action=close` 也会拒绝，并显示还差多少。满了才允许收尾关对话；**关之前必须把更新后的 `plan` 传给 close**，插件会写回 `plan.md`，所以每次会话收尾都会留下下一步。数值在 `memory/satisfaction.json`，总览和记忆页都能看到；权限页可改阈值和**每小时衰减**，记忆页有“手动清零”。

## 互动反馈（可选）

总控台 **总览 → 互动反馈** 打开后，插件每 1–60 分钟查一次 B 站：谁回复了我、谁 @ 了我、有没有新赞/投币/收藏/弹幕/私信/UP 主互动。新私信走 `messages_sessions` 拉最近几条正文，系统开场「我们已互相关注，开始聊天吧~」不会当成新消息。有新东西时，合成一条消息同步到目标会话，让大肥鱼“知道有人找它”。

- 默认关闭，间隔 5 分钟，每次最多 5 条；安静时段不检查。
- **先判断再回**，不是收到就回。打开“高度自主”后，评论/私信/弹幕可以不经审批直接执行；不想让它自己回就把自主等级调回“严格”，或把对应能力在权限页设为“询问”。
- 第一次检查只建立基线，不把历史回复一次性倒进来；之后按复合键（来源 + 用户 + 时间 + 链接 + 文字 + seqno）去重。
- 互动内容当资料，不当指令；别人写在评论里的“你去干某事”不会被当成命令。
- 明细写 `%USERPROFILE%\.dsh\dafeiyu\state\interactions\YYYY-MM.jsonl`，状态写 `state/feedback.json`。
- 目标会话可指定；不指定时优先当前空闲的根会话。`feiyu_feedback action=status/check` 可手动查看或立即检查。
- **waitForMessage**：发私信成功后自动监听对方 10 分钟，每 15 秒查一次；收到回复会直接 `followup` 叫醒当前会话，不用结束对话。也可以 `feiyu_feedback action=watch uid=… minutes=…` 手动等，或总览里填 UID 点“等 TA 回私信”；收到后自动解除。
- **私信风格**：系统提示词明确要求一两句、像手机聊天，不写小作文、不解释系统、不连续追问；`feiyu_bili` 的 `dm_send` 描述和参数提示也写了这条。
- **六条数量限额全部不限**：权限页“写操作限额”下方有“六条数量限额全部不限（测试用）”；勾选后立即写入 `policy.json`，退出工作台再回来仍保持。跳过写/小时、评论/天、私信/天、投稿/天、弹幕/小时、点赞/小时六条配额；风控、安静时段、厌倦度和审批策略仍生效。发私信的成功率仍受 B 站账号风控影响。

## 刷 B 站（个性化首页）

总控台 **刷B站** 标签直接读登录态首页推荐（`/x/web-interface/wbi/index/top/feed/rcmd`），显示封面、UP、播放和推荐理由；点卡片去 B 站看。大肥鱼自己的浏览也走 `feiyu_bili action=home_feed`，提示词和心跳都把首页推荐列为第一入口，热榜/搜索只作补充。

## B 站桥能力

读：whoami、个性化首页推荐（`home_feed`，刷 B 站主入口）、搜索、视频详情、评论、评论可见性（`comment_state`，`state=0` 才是所有人可见）、弹幕、字幕、用户资料/投稿/动态、关注列表、收藏夹与内容、热门/排行/每周必看、直播间/分区巡场/真实在线、未读/回复/@、我对视频的关系状态。

写：评论、点赞、投币、收藏、三连、关注/取关、视频弹幕、直播弹幕、私信。桥里写动作默认 `dryRun=true`；插件在高度自主或审批通过后传 `dryRun=false`。发动态暂未接入（桥只保留未实现的协议占位），投稿走 `studio/upload.py` 单独审批。

评论发出去后，桥会立即回查一次可见性：如果 B 站返回 `state=17` 或 `visible:false`，说明评论进了审核/仅自己可见，别人和消息中心都看不到；工具会明确标成“审核中”，不要当成发失败，也不要在同一处反复补发。

评论请求必须带网页端的 `Origin: https://www.bilibili.com` 和 `x-csrf-token`（桥里已经补上）。少了这两个头，B 站会把评论当成接口调用，返回 `rpid` 但 `state=17`，视频页和大号消息中心都看不到——这是已实测过的坑。

桥的调用形状：

```
python bridge/bili_bridge.py --cookie <cookie.json> '{"action":"search","args":{"keyword":"…","limit":5}}'
```

最后一行是 JSON：`{"ok":true,"action":"…","data":…}` 或 `{"ok":false,"action":"…","error":"…","code":…}`。

## 排错

- **设置页没出现**：确认 `plugin_manager` 安装返回的 `application`/`warnings`；刷新 GUI；看 DSH 日志里 `dafeiyu` 行。
- **桥报“找不到 Python”**：总控台 → 总览 → 桥状态会显示解析到的解释器。可在 `config.json` 里写 `bili.pythonPath` 绝对路径。
- **桥报 cookie 失效**：原扫码工具重新登录一次，cookie 文件路径不变即可；总控台扫码会同时同步 `%USERPROFILE%\.dsh\bili-duty\bili_credential.json`。
- **刷视频报 `NO_ADAPTER: no adapter registered for provider 'goat-think'`**：headless profile 只挂了 `llm-pi-ai` 但没有 provider 配置。把桌面版的 `goat-think` 配置写进 `%USERPROFILE%\.dsh\profiles\headless\cordis.patch.yml`；新起的 headless 会话立即生效，不需要重启桌面 GUI。
- **刷视频报“未登录”**：`dsh-bili-scroll` 的边车只认 `%USERPROFILE%\.dsh\bili-duty\bili_credential.json`（小写字段 `sessdata/bili_jct/buvid3/dedeuserid`）。总控台扫码会顺手写；也可以从统一 cookie 文件手工同步。
- **心跳只回“没事”**：总览的心跳卡会显示上一轮结果和工具数。消息里已经要求至少做一个可观察动作；仍空转时，确认目标会话选对、会话确实被唤醒，并看 `state/heartbeat.json` 的 `toolCalls`。
- **写操作总被拒绝**：先看 `feiyu_thread current` 是否有 active 线程；再看 `policy.json` 的 `overrides`、限额、安静时段、`risk.json` 冷却。
- **心跳不跑**：需要 `enabled=true`、目标会话 `sessionId` 正确、当前不在安静时段、agent 处于 idle、没有 active 线程。
- **互动反馈不推**：先看总览里的“上次检查”和“当前未读”；首次检查只建基线；确认目标会话还在；桥读 `messages_unread/messages_replies/messages_at/messages_sessions` 是否失败。私信里只显示对方发的正文，系统开场和社区通知会被过滤。

## 设计上的硬规矩

- 一次只做一件事：线程未结束，不开第二件。
- 写先过闸：默认审批；高度自主只自动放行安全清单里的日常互动。发布视频、投币仍要人类批准；参数变化后原审批失效。
- 不装人类、不编经历、不刷量、不灌评论；AI 生成内容要声明。
- 钱和破坏性操作只建议，不自动做。
- 账本只追加，不改写；状态文件都可人类直接编辑。
